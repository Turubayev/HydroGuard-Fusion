# Доработка и доказательства готовности

Дата: 2026-10-09.

## Реализовано

Фиксируемая калибровка median/MAD по здоровым датчикам, направленные аномалии давления/расхода/акустики, требование согласованности >=2 каналов и CUSUM. Пропуск сбрасывает накопленное событие, некалиброванный канал не участвует. JSON-модель без pickle. Реальная опциональная интеграция WNTR: давление и расход в сети с утечкой, синтетическая оценка задержки и ложных тревог.

## Аналог и применённый подход

[WNTR](https://github.com/USEPA/WNTR) и [LDIMBenchmark](https://github.com/ldimbenchmark/LDIMBenchmark)

WNTR действительно вызывается в wntr_adapter.py. Из подхода LDIMBenchmark — разделение здоровой калибровки и событийной проверки; сам benchmark toolkit пока не подключён.

## Запуск и проверка

```bash
pip install -r requirements-wntr.txt
python wntr_adapter.py --out runs/wntr_demo
# Реальная телеметрия: time,pressure,flow,acoustic (пустые каналы допустимы)
python hydroguard.py fit healthy.csv --model runs/model.json
python hydroguard.py detect telemetry.csv --model runs/model.json
```

Регрессионные тесты: `python -m pytest -q`. Локальная среда проверки: Windows, Python 3.12. CI проверяет отдельную чистую среду.

## Что требуется для оценки 10/10

Проверить на реальной сети с суточным спросом, перенастроить baseline и пороги на отдельной валидации. Нужны размеченные утечки, аварии насосов, обслуживание и изменения спроса. Измерять ложные тревоги/сутки, долю найденных событий и задержку. WNTR demo — постоянный спрос и одна сеть, акустика отсутствует; аномалия не доказывает утечку и не локализует её.

Инженерные тесты подтверждают поведение кода; они не измеряют клиническую, гидрологическую или коммерческую точность. Метрики на синтетике нельзя переносить на реальные данные. Оценка 10/10 сейчас не заявляется.
